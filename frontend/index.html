⌨ REST commands (optional — the dashboard toggle does the same)

Prefer curl or Postman? The same release / remediate runs through the LaunchDarkly REST API:

  1. One-time setup: create an API access token at Account settings → Authorization → Access tokens (write access to the Test environment) and use it as the Authorization header value. For curl, export it as LD_API_TOKEN (bash: export LD_API_TOKEN=api-… · PowerShell: $env:LD_API_TOKEN="api-…"). The project key is default unless you created a custom project.
  2. Release (turn ON):
    curl -X PATCH "https://app.launchdarkly.com/api/v2/flags/default/helix-auto-scribe" -H "Authorization: $LD_API_TOKEN" -H "Content-Type: application/json; domain-model=launchdarkly.semanticpatch" -d '{"environmentKey":"test","instructions":[{"kind":"turnFlagOn"}]}'
  3. Remediate (turn OFF): the same call with turnFlagOff:
    curl -X PATCH "https://app.launchdarkly.com/api/v2/flags/default/helix-auto-scribe" -H "Authorization: $LD_API_TOKEN" -H "Content-Type: application/json; domain-model=launchdarkly.semanticpatch" -d '{"environmentKey":"test","instructions":[{"kind":"turnFlagOff"}]}'
  4. Run it in Postman: method PATCH, URL as above. Headers: Authorization: <your-token> (no "Bearer") and Content-Type: application/json; domain-model=launchdarkly.semanticpatch. Body → raw JSON: {"environmentKey":"test","instructions":[{"kind":"turnFlagOff"}]} (use turnFlagOn to release). In Postman, edit the auto-added Content-Type so it keeps the ; domain-model=… suffix, or LD returns 400.

Scenario: Helix's Emergency Department starts taking maternity overflow on weekends, so leadership decides ER attendings should see the Maternity Care Pathway too. Right now Dr. Reed (Emergency) can't — let's grant him access without shipping any code.

  1. In LaunchDarkly, open Flags → helix-maternity-pathway → Targeting
  2. Find the rule department is one of maternity and add emergency to the list of values
  3. Click Review and save (add a comment like "ER maternity overflow")
  4. Come back here and click Dr. Reed again → his chart now shows the full pathway, the same information Dr. Alvarez sees

That's the whole point: access is a targeting decision owned in the dashboard, not a code change. To undo it, just remove emergency from the rule again.

⌨ REST commands (optional — beta AI Configs API)

Each persona's model + prompt lives in the helix-clinical-ai AI Config. Read or swap them through the LaunchDarkly AI Configs REST API — note the LD-API-Version: beta header (uses the $LD_API_TOKEN from Part 1's setup):

  1. Read the live config — every variation and its model:
    curl "https://app.launchdarkly.com/api/v2/projects/default/ai-configs/helix-clinical-ai" -H "Authorization: $LD_API_TOKEN" -H "LD-API-Version: beta"
  2. Swap the ED persona's model (Haiku → Sonnet) — updates the helix-scribe-ed variation; the next Generate call uses it:
    curl -X PATCH "https://app.launchdarkly.com/api/v2/projects/default/ai-configs/helix-clinical-ai/variations/helix-scribe-ed" -H "Authorization: $LD_API_TOKEN" -H "LD-API-Version: beta" -H "Content-Type: application/json" -d '{"name":"HELIX-SCRIBE-ED","modelConfigKey":"Anthropic.claude-sonnet-4-5","messages":[{"role":"system","content":"You are HELIX-SCRIBE-ED, a clinical coding assistant for emergency medicine. Extract ICD-10 and CPT codes from the encounter transcript. Return valid JSON only. No markdown."}]}'

AI Configs are a beta API: the PATCH replaces the variation (model + messages), so include the messages you want to keep. The read call is the safe one to demo.
