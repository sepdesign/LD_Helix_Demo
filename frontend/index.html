⚡ Remediate — Flag Trigger

Simulate a billing audit catching an overcoding issue. In a real setup, your monitoring system POSTs to the LaunchDarkly trigger URL — the flag turns OFF system-wide in under 200ms, no deployment needed.

How to set it up:
In LD: Flag settings → Triggers → Add trigger → Generic trigger.
LD gives you a URL. POST to that URL from your monitoring system or from curl:

curl -X POST "https://app.launchdarkly.com/api/v1/flags/triggers/YOUR_TRIGGER_URL"

The flag turns off → SSE fires → this UI updates → no redeploy, no incident bridge.

Extra Credit Python + LD AI SDK

AI Config — helix-clinical-ai

Three AI personas, one flag, zero code changes. The helix-clinical-ai AI Config in LaunchDarkly controls which Claude model and system prompt are used, based on the department context attribute.

Variation Model Use Case
HELIX-SCRIBE-ED claude-haiku-4-5 ED coding — ICD-10 S/T, emergency CPTs
HELIX-SCRIBE-OB claude-sonnet-4-5 OB coding — obstetric ICD-10 O/Z, delivery CPTs
HELIX-PARENT claude-sonnet-4-5 Patient-facing newborn guidance (warm, empathetic)

Swap prompt or model in the LD dashboard → all subsequent calls use the new configuration instantly. No code change. No redeploy.
